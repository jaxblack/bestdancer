# 平台原生发现适配

## 目的

把统一的编辑意图转化为各平台真实页面的操作，而不是拼接未验证的 URL 参数，或把本地排序误称为平台筛选。

统一意图：关键词、视频优先、最近一周、平台原生热度/排序优先、人工细筛。各平台的热度指标只在来源平台内比较；跨平台最终排序由编辑决定。

## 运行边界

- 使用项目 `.venv` 中的 Playwright，通过 `http://127.0.0.1:9222` 连接已登录 Chrome。
- 只操作用户已经登录的平台公开页面；不读取、不写入、不提交 Cookie 或令牌。
- 粗筛只收集元数据和原链接；下载必须在人工入选之后单独执行。
- 操作前先检查元素可见性。筛选面板、弹窗或登录墙未稳定时记录失败原因，不要猜测 URL 参数继续执行。

## 统一候选字段

每个适配器输出以下字段；平台未暴露的字段保留为空：

```json
{
  "source": "平台名称",
  "url": "原始视频或笔记链接",
  "title": "标题或文案摘要",
  "creator": "作者账号",
  "like": 0,
  "play_count": 0,
  "published_at": "ISO 日期或空",
  "source_desc": "可见卡片/详情文本",
  "download_status": "link_only"
}
```

## 已验证适配器

### 抖音

- 入口：`https://www.douyin.com/follow`
- 关键词入口：`https://www.douyin.com/search/{keyword}?type=video`。
- 原生操作：搜索结果分类 `视频`；页面右侧打开 `筛选` 下拉。
- 已确认筛选项：
  - `排序依据`：`综合排序`、`最新发布`、`最多点赞`。
  - `发布时间`：`不限`、`一天内`、`一周内`、`半年内`。
  - `视频时长`：`不限`、`1分钟以下`、`1-5分钟`、`5分钟以上`。
  - `搜索范围`：`不限`、`关注的人`、`最近看过`、`还未看过`。
- 周榜默认组合：`视频` → `筛选` → `排序依据: 最多点赞` → `发布时间: 一周内`；时长和搜索范围保持 `不限`。
- 候选链接：`/video/<id>`。
- 已验证字段：作者、描述、点赞、时长、标签、发布时间。
- 处理逻辑：保留现有 `scripts/douyin_fetch_clean.py` 用于关注流。关键词适配器应读取 `native_filters`，按默认组合操作；筛选面板未展开时返回明确诊断，而不是降级为无筛选或自动下载。
- 快速执行：`.venv/bin/python scripts/douyin_fetch_clean.py --mode discover --source search --week 2026-W29 --keywords urban --top 3`。该命令只生成待人工复核的候选，不下载视频。

### 小红书

- 入口：`https://www.xiaohongshu.com/search_result/?keyword={keyword}&type=51`
- 原生操作顺序：`筛选` → `最新` → `视频` → `一周内` → `收起`。
- 候选链接：`/explore/<note_id>`。
- 已验证状态：用户活动标签中可读取 `div.filter.active`，结果卡可提取 `/explore/` 链接。
- 注意：新建搜索标签的筛选弹层在当前会话中不稳定。适配器应优先复用用户已打开且已筛选的标签；若面板未展开，报告“需要在公开搜索页手动完成筛选”，不要让整批任务失败。

### Instagram

- 入口：`https://www.instagram.com/explore/search/keyword/?q={keyword}`。
- 候选链接：`/p/<shortcode>` 或 `/reel/<shortcode>`。
- 已验证字段：详情页 `og:description` 可读到文案、作者、点赞与发布时间。
- 本次复查：关键词页可见的 `热门` 点击后跳转至全站 `/popular/`，不是当前关键词搜索的排序或筛选。
- 当前边界：桌面关键词搜索未发现可靠的最近一周或热度排序控件。仅收集搜索结果，时间与热度仅能在详情页校验，最终由编辑筛选。

### TikTok

- 入口：`https://www.tiktok.com/search?q={keyword}`。
- 原生操作：点击结果分类 `视频`。
- 候选链接：`/@<creator>/video/<id>`。
- 已验证卡片字段：点赞、文案、作者、`月-日`发布日期。
- 处理逻辑：先使用原生视频分类，再对可读卡片执行最近一周与最低点赞过滤；按点赞降序输出平台内候选。

### Bilibili

- 入口：`https://search.bilibili.com/all?keyword={keyword}`。
- 原生操作顺序：`最新发布` → `更多筛选` → `最近一周`。
- 已验证结果：页面导航为 `order=pubdate`，并附带一周发布区间参数；卡片可读播放量、弹幕、时长、作者、发布日期。
- 候选链接：`/video/BV<id>`。
- 处理逻辑：只解析筛选后的卡片，不再使用本地发布时间猜测；平台内可按播放量作为补充排序依据。

### YouTube

- 入口：`https://www.youtube.com/results?search_query={keyword}`。
- 原生菜单：`过滤`，可见 `上传日期: 本周`、`类型: 长视频`、`优先顺序: 热门程度`。
- 候选链接：`/watch?v=<id>`。
- 已验证字段：标题、频道、观看数、发布时间、时长。
- 注意：菜单选择会重载搜索结果；不同会话中多条件组合的保留方式可能不同。每次点击后必须重新打开过滤菜单并确认当前条件，不要假设 URL 参数恒定。
